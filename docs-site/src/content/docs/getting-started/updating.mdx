# Updating and Troubleshooting

## Updating Beacon

### Home Assistant add-on

1. Go to **Settings → Add-ons → Beacon**. Newer Home Assistant versions call add-ons **Apps**, so the menu may say that instead.
2. If you don't see an update yet, open the add-on store, then use the menu in the top-right corner and choose **Check for updates**.
3. Click **Update**. Leave **Create backup before updating** turned on if Home Assistant offers it, so you can roll back.

From **1.43.2** on, Home Assistant pulls a prebuilt image from GitHub Container Registry (`ghcr.io/asachs01/beacon`) instead of building the add-on on your machine, so updates are a quick download. The image is published for 64-bit Intel/AMD, 64-bit ARM, and 32-bit ARM before that version shows up as an update.

**Coming from 1.43.1 or earlier?** Your first update after 1.43.2 swaps the image Home Assistant built on your machine for the downloaded one. It's a one-time change that happens automatically. Your settings, family members, chores and meal plans carry over.

Home Assistant has deprecated 32-bit ARM (`armv7`). Beacon no longer lists it as a supported architecture. This release still publishes a `linux/arm/v7` image so an existing 32-bit ARM install can finish updating. Future releases may drop that image.

Your family members, chores, settings and meal plans live in the add-on's `/data` folder. They survive updates and are included in Home Assistant backups.

The first time a release with the in-app meal planner rewrites an existing meal plan, it copies `beacon_meal_plans.json` to `beacon_meal_plans.bak.json` in that same folder. The backup is not replaced later. A leftover `meal-plan.json` is imported once and is not deleted. A malformed plan file is left unchanged. See [Meals](/docs/features/meals/).

### Docker

```bash
docker pull ghcr.io/asachs01/beacon:latest
docker stop beacon && docker rm beacon
docker run -d --name beacon -p 3000:3000 \
  -v beacon-data:/data \
  -e SUPERVISOR_TOKEN="YOUR_HA_LONG_LIVED_TOKEN" \
  -e HA_URL="http://YOUR_HA_IP:8123" \
  ghcr.io/asachs01/beacon:latest
```

Make sure the `-v beacon-data:/data` volume is there. Without it, removing the container deletes your Beacon data. With Docker Compose, run `docker compose pull && docker compose up -d`.

## Rolling back a bad update

**Add-on:** Go to **Settings → System → Backups** and restore the backup Home Assistant made before the update. You can restore only the Beacon add-on rather than the whole system.

**Docker:** Run a specific version tag instead of `latest`, for example `ghcr.io/asachs01/beacon:1.40.2`. Each release publishes that image before the version is offered. Older tags are on the [package page](https://github.com/asachs01/beacon/pkgs/container/beacon).

If an update breaks something, please [open an issue](https://github.com/asachs01/beacon/issues). We'd much rather hear about it than have you quietly roll back.

## Finding the logs

| What you're debugging | Where to look |
|---|---|
| The add-on won't install, update, or start | **Settings → System → Logs**, then choose **Supervisor** |
| The add-on starts but misbehaves | The **Log** tab on the Beacon add-on page |
| Something wrong on the display itself | The browser console (F12 on a computer, or remote debugging on a tablet) |
| Docker | `docker logs beacon` |

When you file a bug, include your Beacon version, your Home Assistant version, the device and browser on the display, and the relevant log lines. A full log is better than a screenshot of part of it.

## Common problems

### The update fails

Updates pull `ghcr.io/asachs01/beacon:<version>`. If the pull fails, the Supervisor log names the registry error or the missing tag. Your installed version keeps running, so nothing is lost. Check that Home Assistant can reach `ghcr.io`, check for updates again, and if it still fails, open an issue with that log.

### The update finished but the screen looks the same or says it can't connect

The add-on restarts at the end of an update, and for a few seconds the Beacon panel can show a "Cannot connect" error. Wait a moment and reload. If a wall tablet still shows the old version, it is holding a cached copy: hard-refresh the page, or restart the kiosk browser (in Fully Kiosk Browser, use **Clear cache** and reload). The add-on's **Log** tab shows the version that's actually running.

### 32-bit ARM (armv7)

Home Assistant reports `armv7` as a deprecated architecture. Beacon's manifest lists amd64 and aarch64 only. The image for this release is still published for `linux/arm/v7` so an existing 32-bit ARM device is not left without a pullable update. Future releases may stop publishing that image.

### I turned on Kiosk Mode and can't get the menu back

Long-press the top corner of the screen for about 2 seconds, or tap it 3 times quickly. On a keyboard, hold Escape for about 2 seconds. If a family member has a PIN, Beacon asks for it first. This needs **1.40.2** or later. See the [kiosk FAQ](/docs/reference/faq/#how-do-i-hide-the-sidebar-for-wall-tablets--kiosk-setups) for details, including Kid Display.

### The dashboard shows tomorrow's meals in the evening

Versions before **1.40.1** worked out "today" in UTC, so in US time zones the meal widget moved to the next day in the afternoon or evening. Update to the latest version. See [Meals](/docs/features/meals/).

### Changing the date on the dashboard doesn't load that day's events

Fixed in **1.40.3** ([#62](https://github.com/asachs01/beacon/issues/62)). Update to the latest version.

### Notifications aren't firing

1. Notifications only fire for timed events, not all-day events.
2. The browser needs notification permission. Check it in your browser's site settings.
3. The Beacon tab has to be open on at least one device. It checks for upcoming events about once a minute.
4. The default lead time is 10 minutes. Check **Settings → Calendar** if you expected a different one.

See [Notifications](/docs/features/notifications/) for more.

### Beacon shows "Demo Mode" or an empty calendar

Beacon can't reach Home Assistant, or Home Assistant has no `calendar.*` entities. See the [FAQ troubleshooting section](/docs/reference/faq/#troubleshooting).
