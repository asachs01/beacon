# Family Members

Family members are the people in your household. Each member gets a name, an avatar, a color, a role, and an optional PIN. Members are used for chore assignment, the leaderboard, and visual identification throughout the app.

---

## Adding a family member

1. Click the **gear icon** (Settings) in the bottom of the sidebar
   - On mobile, tap **More** in the bottom tab bar, then tap **Settings**
2. The "Family Members" modal opens showing your current members (or "No family members yet" if none exist)
3. Click **+ Add Member**
4. Fill in the form:
   - **Name**: Enter the member's name (required)
   - **Avatar**: Pick an emoji from the categorized grid (see below)
   - **Color**: Pick a color from the 8-color palette
   - **Role**: Select Parent or Child
   - **PIN**: Optionally enter a 4-6 digit numeric PIN
5. Click **Add Member**

The member is saved immediately to the browser's localStorage and (when possible) synced to Home Assistant input_text helpers.

## Roles

Each family member has one of two roles:

| Role | Description |
|------|-------------|
| **Parent** | Can unlock privileged actions using the deployment's parent PIN or an enrolled parent member PIN. |
| **Child** | Can use an authorized Kid Display for their own chores and routine. |

The secured Family server enforces parent versus display sessions and restricts sensitive writes. A client-side role label alone does not grant access.

---

## PIN setup

The add-on requires a private 6–8 digit `parent_pin` option; standalone Docker requires `BEACON_PARENT_PIN` (also 6–8 digits). Unlocking the parent session is needed for privileged actions. A parent member can also have an optional PIN to unlock the parent session, while a Kid Display may require that member's own PIN. Set member PINs through the secured Family server; it stores PIN hashes, not plaintext in browser localStorage. Do not share the parent PIN with kiosk devices.

Parent unlock expires **10 minutes after PIN entry**, even if you are still using the app: polling does not renew that cookie. Enter the configured 6–8 digit parent PIN again to manage Family or HA. Kid Display sessions are different: they have a **24-hour sliding** lifetime refreshed by normal display session polling.

## Calendar assignment

Each family member can be linked to a Home Assistant calendar entity. This powers the per-member columns in the **Family** dashboard layout (see [Dashboard](/docs/features/dashboard/)).

### Assigning a calendar

1. Open **Settings > Family Members**
2. Click the **pencil icon** on the member's card
3. In the edit form, find the **Calendar** dropdown — it lists all calendar entities discovered from your Home Assistant instance
4. Select the calendar that belongs to this member
5. Click **Save Changes**

Once assigned, the member's dashboard column will show only events from their linked calendar. Events from calendars that are not assigned to any member appear in the **"Other"** column.

### Tips for calendar setup

- **Google Calendar**: Each Google account connected to HA automatically creates calendar entities (e.g., `calendar.john_gmail_com`). Assign the appropriate one to each family member.
- **Kids without accounts**: If a child doesn't have their own Google account, create a shared sub-calendar on a parent's account dedicated to that child's events, or use Home Assistant's **Local Calendar** integration to create a calendar entity for them.
- **Multiple calendars per person**: Only one calendar entity can be assigned per member. If a person uses multiple calendars, consider merging them into one or picking the primary one.

## Editing a family member

1. Open the Family Members modal (gear icon in sidebar)
2. Find the member you want to edit
3. Click the **pencil icon** on their card
4. The form opens with the member's current data pre-filled
5. Modify any fields
6. Click **Save Changes**

---

## Removing a family member

1. Open the Family Members modal
2. Find the member you want to remove
3. Click the **trash icon** on their card
4. The button changes to show **Confirm?** (you have 3 seconds to click again)
5. Click **Confirm?** to permanently remove the member

Removing a member does not delete their chore completions or streak history. However, they will no longer appear in the Chores panel or Leaderboard.

## Data storage

In the Family add-on and standalone Docker, the server's `/beacon-collection/*` API is the source of truth for family members, chores, and completions, persisted under `/data`. Browser localStorage is a cache for quick initial rendering. Mount a `/data` volume in Docker and back up add-on data through Home Assistant. With server enforcement enabled, member PIN values stay on the server as hashes rather than being sent to the browser.

Clearing a browser's cache/preferences does **not** erase the server's collection; the next read refreshes it. Direct development/native installations without the server may keep local-only data on that device instead.

## Troubleshooting

### Family members do not appear after clearing browser data

In the add-on/Docker deployment, check that the server is reachable and its `/data` storage is intact. Browser localStorage should refill from the server. In direct development mode, local-only data can be lost when clearing site data.

### The "Add Chore" button does not appear

The Add Chore button appears when there is at least one family member defined. If no members exist, the Chores panel shows "Add family members first to assign chores."

### Changes do not sync across devices

Make sure both displays use the same Family server (authenticated HA ingress for the add-on, or the same HTTPS standalone URL). If changes still differ, check the server logs and persistence volume rather than manually copying localStorage between devices.
