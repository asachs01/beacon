# Press-to-talk

The microphone only works when Beacon is opened over **HTTPS**, or on `localhost`. Many wall tablets use plain HTTP (`http://192.168.x.x` or `http://homeassistant.local:8123`). On those, only the text box shows. To use the mic, open Beacon through Home Assistant over HTTPS. See Home Assistant's [remote access](https://www.home-assistant.io/docs/configuration/remote/) documentation.

This needs Beacon **1.46.0** or later.

## Upgrading from an earlier version

If you already copied Beacon's voice intents into Home Assistant, update them. Chore completion by voice now goes through a new `rest_command` in `beacon/custom_intents/beacon_rest_command.yaml`. The install script `beacon/scripts/install-voice-intents.sh` copies the sentence file, the intent file, and that rest command file. Until you re-run the script or copy the files over by hand, the old intents keep writing to `todo.chores`.

1. Update the files:

   ```bash
   beacon/scripts/install-voice-intents.sh /config
   ```

   That copies `custom_sentences/en/beacon.yaml`, `custom_intents/beacon.yaml`, and `beacon_rest_command.yaml`.

2. In `configuration.yaml`, if it is not already there:

   ```yaml
   intent_script: !include_dir_merge_named custom_intents
   ```

3. Copy the `rest_command` block from `beacon_rest_command.yaml` into `configuration.yaml`. The install script does not add that block for you. Replace `ADDON_SLUG` with the slug at the end of the add-on page URL (**Settings → Add-ons → Beacon**). From Home Assistant core, the add-on listens on port 3000 of the Supervisor network. Chore completion is `POST http://ADDON_SLUG:3000/beacon-action/complete-chore`. "What chores are left" is `GET http://ADDON_SLUG:3000/beacon-action/chores-left?member=`.

4. Restart Home Assistant so the new rest commands exist. Reloading Conversation is not enough for a new `rest_command`. After a restart, reload Conversation under **Developer Tools → YAML** if you only changed sentences.

The wall's hold-to-talk button can still complete a chore through Beacon's own voice API if Assist errors because the rest command is missing. A speaker that is not the wall still needs the updated intents and rest commands. A conversation agent has to be set up; the built-in Home Assistant agent is enough (**Settings → Voice assistants**).

---

The wall display has a hold-to-talk control. Press and hold the microphone, say one command, and let go. Beacon shows what it heard and the reply, then the card goes away on its own after about seven seconds. Nothing listens until you hold the button. There is no wake word.

A keyboard button next to the mic opens the same card with a text box. That box is always there when the voice button is on, including on plain HTTP.

## Where the button is

The buttons sit at the lower left of the wall, including in kiosk mode and on a Kid Display. The quick-add button stays at the lower right.

Turn it on or off under **Settings → Display → Voice button**.

| Where Beacon is running | Default, until you save a choice |
| --- | --- |
| Home Assistant add-on | On |
| Standalone browser or the Android app | Off |

The settings reference lists the literal default as `true`. Until a true or false has been saved, the add-on shows the button and a standalone browser hides it. A saved on or off value stays as you set it. Resetting settings returns to that same place-based default, then saves it.

**PIN.** Speaking a chore does not ask for a PIN. Checking a chore on the wall still does not ask for a PIN. The family PIN only reveals kiosk navigation and exits Kid Display.

### Microphone permission

The Web Speech API only runs in a secure context (HTTPS or localhost), as described at the top of this page. The first time you hold the mic, the browser asks for microphone permission. Beacon never opens the microphone on its own. Browsers without the Web Speech API also keep the text box and hide the mic.

## What you can say

| Say | Result |
| --- | --- |
| "Mark X as done", "I finished X", "X is done", "Ada finished X" | Completes that chore in Beacon's chore chart. Fires `beacon_chore_completed`, re-checks that person's privilege switch, and fires `beacon_all_chores_done` (and turns the switch on) only when this completion finishes their chores for today. Does not update `todo.chores`. |
| "Complete the X chore" | Also completes a Beacon chore, same as the row above. |
| "Check off …", or a bare "complete …" / "finish …" | Still updates a Home Assistant to-do item. These are not chore completions. |
| "What chores are left", "What does Ada have left" | Reads today's remaining chores from Beacon's chore chart, not `todo.chores`. |
| If the match is unclear | Beacon asks which chore, or which person, and saves nothing. |

**Changed in 1.46.0.** Phrases like "Mark X as done", "I finished X", "X is done", and "Name finished X" used to update `todo.chores`. They now write to Beacon's chore chart, fire the same events as checking the chore on the wall, and re-check the privilege switch. "What chores are left" also reads that chart. "Check off …" and a bare "complete …" still update a to-do item. If you already copied the older intent files into Home Assistant, see [Upgrading from an earlier version](#upgrading-from-an-earlier-version).

The completion is stored in Beacon's family data (`beacon_completions.json`), the same place a tap on the chore screen writes. It matches the chore title loosely, and a person's name when you say one.

- One matching assignment: Beacon marks it done, updates that person's streak, fires `beacon_chore_completed`, and re-evaluates their privilege switch. If this completion finishes every chore assigned to them today, Beacon also fires `beacon_all_chores_done` and turns the switch on.
- The title matches one chore assigned to more than one person: the reply asks who finished it, and nothing is saved.
- Several chores match: the reply lists them and asks which one.
- It was already done today: the reply says so, and Beacon does not fire the events again.

See [Chore privileges](/docs/features/chore-privileges/) for the events and the privilege switch.

Other commands the first version handles:

| Say | Result |
| --- | --- |
| "Add milk to the grocery list", "Put eggs on the shopping list" | Adds the item on the matching Home Assistant todo list |
| "What's on the calendar today", "Any events today" | Reads today's events |
| "Show the calendar" | Switches the wall to that view |

Grocery adds still use the Home Assistant todo list (`todo.grocery` unless the intent file names another one). "What's on the calendar today" from Assist reads `calendar.family`. Beacon's own voice API reads every calendar.

The wall also subscribes to the Home Assistant event `beacon_navigate` and switches views when Assist fires it from another device. That subscription needs the wall's websocket, which needs the add-on's long-lived access token (`ha_token`) or an ingress token. The wall's own "show the …" command still navigates from the voice reply when the websocket is not connected.

## What happens to the words

1. In the Home Assistant add-on, if a conversation agent is available, Beacon calls `conversation.process` (websocket when the wall is signed in, otherwise the REST service through the add-on).
2. If that reply is an error, or there is no agent, or Beacon is not the add-on, Beacon POSTs the same text to `/beacon-action/voice`.

Assist uses the same chore endpoints once the rest commands are installed. `BeaconCompleteChore` and `BeaconCompleteChoreByPerson` call `rest_command.beacon_complete_chore`, which POSTs to `/beacon-action/complete-chore`. `BeaconChoreStatus` and `BeaconChoreStatusByPerson` call `rest_command.beacon_chores_left`, which GETs `/beacon-action/chores-left`. The spoken reply is whatever that endpoint returns, including the question when more than one chore matches.

## Home Assistant setup

Follow the steps in [Upgrading from an earlier version](#upgrading-from-an-earlier-version) to install or update the sentence files, include the intent scripts, copy the `rest_command` block, and restart Home Assistant.

Then:

1. A conversation agent has to be set up (the built-in Home Assistant agent is enough). **Settings → Voice assistants**.
2. Optional: set the add-on's long-lived access token (`ha_token`) if you want the wall to follow `beacon_navigate` from a speaker in another room.

If the rest commands are not installed yet, Assist answers with an error and the wall falls back to `POST /beacon-action/voice`, which completes the chore or reads the chart itself. A speaker that is not the wall still needs the rest commands.
