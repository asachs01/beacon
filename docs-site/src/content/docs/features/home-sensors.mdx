# Home sensors

Home sensors is a dashboard card for a few Home Assistant entities: a temperature, a door, the garage, or whether the washer is done. It is read-only. It does not toggle devices, call services, or show camera feeds.

The card is **off** until you turn it on. Existing dashboards are unchanged, and the card is not part of the Family, Classic, or Compact layout presets.

This needs Beacon **1.53.0** or later. The live socket only streams the entities you picked starting in **1.53.1**. See also [Home Assistant calls Beacon allows](/docs/reference/ha-calls/).

## Turn it on

1. Open **Settings → Integrations → Home sensors**.
2. Turn on **Home sensors card**.
3. Pick the entities you want under **Sensors**. The list is a separate request, `GET /beacon-api/home-sensors/entities`. Each row is only `entity_id`, `friendly_name`, `domain`, `device_class`, and `unit` — not the current state. In standalone mode, that list is whatever the Home Assistant user for the long-lived `HA_TOKEN` can see. Each entity can have its own optional **Name** and **Icon** (an emoji or a short label). Leave the name blank to use Home Assistant's friendly name.
4. Turn on **Settings → Appearance → Advanced Dashboard** if it is not already on.
5. On the dashboard, choose **Edit Dashboard** and add the **Home sensors** card. You can put it in the top bar, the main area, or the sidebar.

The picker does not include `camera` entities. The card never shows a camera image.

It works in the Home Assistant add-on and in standalone mode (`HA_URL` and `HA_TOKEN`). The browser does not need its own token. The server subscribes with the token it already uses, on `/beacon-ws/ha`, and forwards only the entities selected for this card. If the card is off, or you have not picked anything, that socket delivers no entity states. Picking another entity starts sending it on the socket that is already open. You do not reconnect.

The socket is still read-only by allowlist: `get_states`, a `state_changed` subscription, unsubscribe of a subscription this page opened, and `ping`. Other commands are refused on the server and are not sent to Home Assistant. If the browser itself is signed in to Home Assistant, the card uses that connection instead.

The picker catalog does not include state values. In Beacon 1.53.1 and earlier, any device that can open Beacon can open it. From Beacon **1.54.0**, a device that opens Beacon directly has to be [paired](/docs/getting-started/pairing/) first. Separately, from 1.53.1 Beacon only passes along the Home Assistant calls its own screens use. See [Home Assistant calls Beacon allows](/docs/reference/ha-calls/).

:::caution
Before Beacon 1.54.0, anyone who could reach Beacon's port could use its Home Assistant access (see the [security advisory](https://github.com/asachs01/beacon/security/advisories/GHSA-rj98-fx8p-896h)). Update to **1.54.1** or later and [pair your devices](/docs/getting-started/pairing/). Even then, keep Beacon's port on your trusted home network (your LAN) and never forward it to the internet or expose it beyond your LAN. In the add-on, use the Home Assistant sidebar panel (ingress) where you can; it sits behind your Home Assistant login. If you need remote access, use the add-on's ingress panel, Home Assistant's own remote access, a VPN, or a reverse proxy that requires authentication.
:::

From Beacon **1.54.0**, a device that opens Beacon directly on its port pairs once first. See [Pairing a device](/docs/getting-started/pairing/).


## What you see

Each row is a name and a state. Temperatures keep their unit. A door, garage, or window shows **Open** or **Closed**. A lock shows **Unlocked** or **Locked**. A running sensor shows **Running** or **Idle**. Other binary sensors show **On** or **Off**.

Updates arrive over Home Assistant's websocket (`get_states`, then `state_changed`). The card does not poll.

| State | What the card shows |
| --- | --- |
| `unavailable` | **Unavailable** |
| `unknown`, or a blank state | **Unknown** |
| No update for 3 hours | **No update in 3 h** (or the real age, such as **No update in 4 h**) |
| A current value | The value, with its unit when Home Assistant sends one |

Three hours is the staleness window (`HOME_SENSOR_STALE_MS` in `src/home-sensors/format.ts`). Freshness uses the newest of `last_reported`, `last_updated`, and `last_changed`. A stale row does not keep showing the old number or the old door state.

If Home Assistant removes an entity, the row says **Unavailable**.

## Who can see it

The card is hidden while [guest mode](/docs/features/guest-mode/) is on. It is registered as the `homeSensors` feature with kind `sensors`, which guests cannot see unless that registration is changed to allow them.

It is not on [Kid Display](/docs/features/kid-display/). Kid Display still shows only that family member's routine and chores.
