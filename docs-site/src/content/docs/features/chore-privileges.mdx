# Chore privileges

Beacon can turn on a Home Assistant entity when a child finishes the chores assigned to them today, and it fires events that automations can listen for. Both are optional. Families that never pick a privilege switch and never import the blueprint keep the same chore behavior as before. This needs Beacon **1.45.0** or later.

The check uses the chore day, the same boundary as the chore chart. That day starts at **Settings → Chores → Daily Reset Time**. When the reset time is unset, empty, or not a valid `HH:mm`, the chore day starts at local midnight. It does not use the UTC date. An evening in US time zones is still today even though the stored timestamp is already the next day in UTC.

A completion at 23:00 with the reset set to 04:00 stays on that chore day until 04:00. The privilege switch, the `local_date` on `beacon_chore_completed` and `beacon_all_chores_done`, and "what chores are left" all use that same day. There is no settings or completion migration: stored timestamps stay as they are, and a family that leaves the reset at `00:00` keeps the midnight boundary.

## Privilege switch

The setting is per child, not a global Settings toggle.

1. Open **Settings** (gear icon; on a phone, **More** then **Settings**)
2. Open **Family Members** and edit a member whose role is **Child**
3. Set **Privilege switch**

The picker lists only these Home Assistant domains:

| Domain | Typical use |
|--------|-------------|
| `switch` | A Wi-Fi plug, a smart outlet, or a template switch |
| `input_boolean` | A toggle helper an automation already watches |
| `light` | A lamp |
| `fan` | A fan |

The default is **None**. Nothing is stored until you pick an entity. Clearing the picker removes the field. Parents do not get this control; changing a child to a parent clears it. Existing family members, chores, completions, settings, and add-on options are left as they are. There is no migration.

**PIN.** This does not add a PIN and does not change the one you already have. Checking a chore does not ask for a PIN. The family PIN is still used only for the parent actions listed under [PIN setup](/docs/features/family/#what-a-family-pin-unlocks), such as revealing kiosk navigation and leaving Kid Display. If nobody has a PIN, those two stay on the gesture or the confirm button, the same as before.

### When the entity turns on and off

Beacon calls Home Assistant `turn_on` or `turn_off` on that entity:

| Situation | Service |
|-----------|---------|
| Every chore assigned to that child today is checked | `turn_on` |
| A chore is unchecked, or some of today's chores are still open | `turn_off` |
| The child has no chores assigned | `turn_off` (zero chores is not "all done") |
| The chore day rolls over at the daily reset time | `turn_off` |
| Beacon loads, or the add-on process starts | Whichever of the above matches the current chore day |

A manual toggle in Home Assistant is left alone until the next one of those moments. Beacon does not keep forcing the entity every few seconds during the day.

"Today" is the chores assigned to that member and completed during the current chore day. The chore day runs from the daily reset time until the next one. With the reset left at midnight, that is the local calendar day. Weekly and one-time chores count the same way once they are assigned: if they are on the child's list, they have to be checked during this chore day for the switch to turn on.

### Where the call runs

- An open Beacon page calls the service itself. In the add-on that goes through the add-on's Home Assistant proxy. From **1.53.1**, that proxy only allows the entity picked as a child's **Privilege switch**. If you change it, save the family settings first. See [Home Assistant calls Beacon allows](/docs/reference/ha-calls/). In standalone mode it uses the long-lived access token, if one is configured.
- The add-on server also sets the switches about 15 seconds after it starts, and again when the chore day changes, even if no screen is open. It checks every 30 seconds, so the reset can be up to half a minute late.
- The server asks Home Assistant for `time_zone` (`GET /api/config`) and uses that zone for the chore day. If that request fails, it uses the add-on process timezone via the same chore-day helper. It does not use UTC. The page uses the device timezone. Those should be the same zone as Home Assistant. If they are not, the screen and the add-on can disagree about when the reset time arrives.
- Standalone Beacon (the browser or Android app talking to Home Assistant without the add-on server) has no background scheduler. The reset turns the switch off only while a Beacon page is open. If the page is closed across the reset, the switch stays where it was until the next time Beacon opens and re-evaluates.
- If Home Assistant cannot be reached, the chore still saves. Beacon logs the failed service call and continues.

## Events

Events are fired by the **add-on server**, with the Supervisor token, when someone checks or unchecks a chore in Beacon. The browser tells the add-on (`POST /beacon-action/chore-events`) after the completion is saved. Any client using the add-on — the wall tablet, another browser on the ingress URL, Kid Display — goes through that path.

Standalone mode does not fire these events. There is no add-on process to post them. The chore still saves. Beacon logs that the events were skipped.

A failed post never undoes the checkmark.

Checking a chore that is already complete today does not fire again. Unchecking a chore that was not complete today does not fire.

From **1.46.0**, completing a chore by voice fires these same events and re-checks the privilege switch. See [Press-to-talk](/docs/features/press-to-talk/).

### `beacon_chore_completed`

Fired on every real check and uncheck.

| Field | Type | Meaning |
|-------|------|---------|
| `member_id` | string | Beacon family member id |
| `member_name` | string | Name shown in Settings |
| `chore_id` | string | Chore id |
| `chore_title` | string | Chore name |
| `completed` | boolean | `true` when checked, `false` when unchecked |
| `local_date` | string | Chore day, `YYYY-MM-DD` |

### `beacon_all_chores_done`

Fired only when a check is what makes that member's chores for the current chore day complete (every assigned chore is done, and they have at least one). It is not fired when a chore is unchecked, when the member has no chores, or when that chore day's list was already complete. `local_date` is that chore day.

| Field | Type | Meaning |
|-------|------|---------|
| `member_id` | string | Beacon family member id |
| `member_name` | string | Name shown in Settings |
| `local_date` | string | Chore day, `YYYY-MM-DD` |

In an automation, `trigger.event.data.member_name` (and the other fields) are those values.

```yaml
trigger:
  - platform: event
    event_type: beacon_all_chores_done
action:
  - service: switch.turn_on
    target:
      entity_id: switch.ada_wifi
```

## Example blueprint

The repo includes one automation blueprint:

`blueprints/automation/beacon/chores_unlock_wifi.yaml`

It listens for `beacon_all_chores_done` and turns on an entity you pick. You can limit it to one child by typing that child's name exactly as it appears in Beacon. Leave the name blank to run for every member.

It does **not** turn the device off when the chore day rolls or when a chore is unchecked. Use the Privilege switch in Settings for that, or write a second automation on `beacon_chore_completed` with `completed: false`.

Import it in Home Assistant:

1. **Settings → Automations & scenes → Blueprints → Import blueprint**
2. Paste:

```text
https://github.com/asachs01/beacon/blob/main/blueprints/automation/beacon/chores_unlock_wifi.yaml
```

3. Create an automation from the blueprint and choose the entity.

The URL works after this file is on the default branch. Home Assistant reads the blueprint from GitHub; it is not installed into `/config` by the add-on.
